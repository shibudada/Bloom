Mobile information architecture

One screen, one clinical decision.

  3. Review and prescribe.Photon is the final focused transition, not a permanently visible panel.
COSS boundary

Own the clinical composition, not the primitive.

COSS should provide accessibility, keyboard behavior, overlays, and control states. Bloom should provide clinical meaning and workflow.

Usage rules

Constraints that keep the system calm.

These rules are the acceptance criteria for the implementation pass.

Do not color ordinary selection green.

Use neutral selected surfaces. Reserve green for success, readiness, or connected state.

Do not stack desktop panels on mobile.

Convert the queue, patient task, and prescription review into routed or stateful screens.

Do not ship clickable dead ends.

Implement the local prototype behavior, disable with clear reason, or remove the control.

Do not remove focus without replacement.

Every interactive element receives a consistent visible focus ring.

Do not make the helper the task.

The agent supports note and plan work; it does not displace the patient's clinical workflow.

Do not create a parallel primitive library.

Use COSS behavior and semantic tokens; keep customization in Bloom compositions.
